# SRM 第一期需求方案：供应商自主注册与准入审批

文档版本：V1.0。编写日期：2026-10-30。用途：内部产品评审、开发任务拆分与交付验收。

## 本次 MVP 范围调整

根据开发过程中的确认，本次暂不接入邮件：使用邮箱和密码直接注册、登录，邮箱验证、邮件找回密码及真实邮件送达不属于本次验收范围。以下章节中涉及邮件验证和发送的原始需求留作后续阶段参考；站内通知仍属于本次必需交付内容。

## 1. 目标与需求基线

第一期完成供应商自主注册、资料提交、采购管理员审批、驳回重提和正式建档的完整闭环，并具备必要的账号管理、权限隔离与历史追溯能力。

本期仅保留供应商自主注册入口。供应商注册时可以选填介绍人姓名，通常为某位业务员的名称，作为线索记录。介绍人不参与注册、资料维护或审批，也不会因被填写而获得任何系统权限。

### 1.1 已确认范围

- 供应商自主注册并申请准入。
- 注册时可选填介绍人姓名。
- 采购管理员执行准入审批。
- 提供业务闭环所需的用户、角色与数据权限。
- 提供申请状态、审批意见、历史记录和正式供应商档案。

### 1.2 建议默认规则

以下规则作为可执行方案的默认基线，属于待业务评审确认的产品选择；后续调整应同步更新本文件及相关验收标准。

| 项目         | 默认规则                                                           |
| ------------ | ------------------------------------------------------------------ |
| 适用企业     | 中国大陆企业，以统一社会信用代码识别主体                           |
| 账号验证     | 邮箱验证注册，手机作为业务联系方式                                 |
| 企业与账号   | 一个供应商账号管理一家企业，一家企业仅有一个主账号                 |
| 审批方式     | 单级审批，任一拥有权限的采购管理员均可处理                         |
| 驳回处理     | 驳回后允许修改并重新提交，不设永久拒绝状态                         |
| 审核期间修改 | 禁止修改已提交资料，本期不提供撤回                                 |
| 准入后修改   | 企业主体、准入资料及介绍人记录锁定，资料变更流程后续建设           |
| 介绍人       | 选填自由文本，不关联内部账号，不校验员工是否存在                   |
| 附件         | PDF、JPG、PNG；单文件不超过 10 MB，每次申请最多 10 个文件          |
| 通知         | 站内通知为必需；验证及密码找回依赖邮件服务，审批结果邮件为可选增强 |

### 1.3 本期不包含

- 业务员登记供应商、邀请注册、代填资料、引入进度工作台。
- 业务员角色、介绍人账号关联、介绍人业绩统计及介绍人通知。
- 多级审批、会签、加签、转交、代理审批和自定义流程设计。
- 多账号共同管理企业、主账号转移、自助认领已有企业。
- 准入后资料变更审批、资质到期复审、停用、退出和黑名单。
- 询报价、采购订单、合同、结算、绩效评分和银行账户管理。
- 自动工商核验、OCR、境外企业注册及历史供应商批量导入。

## 2. 业务流程与状态

```text
访问注册入口
  → 验证邮箱并创建供应商账号（可选填介绍人姓名）
  → 填写企业资料、上传资质、保存草稿
  → 提交准入申请
  → 采购管理员审核
      → 通过：生成供应商编号，形成正式供应商档案
      → 驳回：填写原因，通知供应商
          → 供应商修改资料并重新提交
          → 再次进入采购管理员审核
```

账号注册成功不代表企业准入成功。未准入供应商只能使用入驻申请相关功能，不能因此获得正式供应商业务权限。

| 状态   | 含义                 | 供应商操作               | 采购管理员操作     |
| ------ | -------------------- | ------------------------ | ------------------ |
| 草稿   | 尚未正式提交         | 编辑、保存、上传、提交   | 不进入审批队列     |
| 待审核 | 已提交并冻结本次版本 | 查看资料、进度与历史     | 查看、通过、驳回   |
| 已驳回 | 当前版本未通过审批   | 查看原因、编辑、重新提交 | 查看详情及历史     |
| 已准入 | 审批通过并正式建档   | 查看正式档案与历史       | 查看正式档案与历史 |

允许的状态流转为：草稿 → 待审核；待审核 → 已驳回或已准入；已驳回 → 待审核。已驳回资料在编辑和保存期间仍显示为已驳回，直至重新提交。已准入在本期没有后续状态流转。

## 3. 角色与权限

| 角色       | 功能范围                                       | 数据范围                                       |
| ---------- | ---------------------------------------------- | ---------------------------------------------- |
| 供应商     | 注册、维护草稿、上传资质、提交、查看结果与档案 | 仅所属企业及其申请、附件、审批历史             |
| 采购管理员 | 审核申请、查看审批历史、查询正式供应商         | 全部已提交申请及正式供应商                     |
| 系统管理员 | 管理内部用户、角色、权限及必要系统配置         | 系统管理范围；业务审批需单独授予采购管理员权限 |

### 3.1 权限规则

- 自主注册只能获得受企业归属约束的供应商能力，不能自行选择内部角色。
- 采购管理员等内部角色必须通过受权限保护的用户管理页面明确授予具体用户，分配和移除均可查看。
- 介绍人姓名不参与身份识别、账号匹配、角色分配或数据范围计算。
- 采购管理员不得代替供应商修改申请资料；发现问题通过驳回处理。
- 采购管理员默认看不到未提交的供应商草稿；已驳回后的未提交修改同样不可见，审核端查看最近一次提交快照。
- 页面权限、业务操作权限和记录范围分别校验；直接调用接口必须受到同样限制。
- 附件预览和下载必须验证企业归属或审核权限，不能以公开文件地址绕过权限。
- 系统账号管理不提供供应商企业认领或主账号迁移能力，相关异常由人工核实并登记处理。

## 4. 功能需求

### 4.1 账号注册与登录

| 编号   | 功能       | 业务规则                                                                |
| ------ | ---------- | ----------------------------------------------------------------------- |
| REG-01 | 自主注册   | 公开入口填写邮箱、密码及可选介绍人姓名，验证邮箱后激活供应商账号        |
| REG-02 | 邮箱验证   | 验证凭证有有效期、不可重复使用；发送及验证实施频率限制                  |
| REG-03 | 登录与退出 | 激活账号可登录，退出后会话失效；登录后根据身份和申请状态进入对应首页    |
| REG-04 | 找回密码   | 通过已验证邮箱完成密码重置；重置凭证有有效期且仅可使用一次              |
| REG-05 | 注册唯一性 | 同一邮箱不能重复建立有效账号；重复注册不产生重复企业或申请              |
| REG-06 | 介绍人记录 | 可为空；非空时去除首尾空白，长度上限 100 个字符，作为普通文本保存和展示 |

介绍人字段使用“介绍人姓名（选填）”的表达，并提示“如有介绍您注册的业务员，请填写其姓名”。不提供内部员工搜索、下拉名录或联系方式查询，不要求供应商知道业务员账号。

介绍人姓名先随注册信息保存，再带入申请草稿。草稿或已驳回状态下允许修改；每次正式提交均将当时的介绍人姓名写入申请快照。审批通过后档案保留获批版本的介绍人姓名，不覆盖历史版本。

### 4.2 企业资料与资质

| 分组     | 字段                           | 要求                               |
| -------- | ------------------------------ | ---------------------------------- |
| 主体信息 | 企业法定名称                   | 必填，与证照一致                   |
| 主体信息 | 统一社会信用代码               | 必填，校验格式并用于企业唯一性约束 |
| 基础信息 | 注册地址                       | 必填                               |
| 基础信息 | 企业简介                       | 选填                               |
| 供应能力 | 供应品类                       | 必填，至少选择一项                 |
| 供应能力 | 主要产品或服务                 | 必填，文本说明                     |
| 联系信息 | 联系人姓名、联系电话、联系邮箱 | 必填，电话及邮箱校验格式           |
| 线索信息 | 介绍人姓名                     | 选填，注册时带入，与联系人分开保存 |
| 必备资质 | 营业执照                       | 至少上传一个有效附件               |
| 补充资质 | 行业许可证、认证证书或其他材料 | 选填，填写材料名称并上传文件       |
| 提交声明 | 信息真实性确认                 | 每次提交前必须勾选                 |

供应品类采用管理员维护的简单选项字典，支持新增、修改名称及停用；停用项保留历史展示，不能在新申请中选择。不提供多层分类和按品类动态配置必填资料。

- 草稿允许资料不完整，但已填写字段仍需满足基本格式及长度要求。
- 保存成功后重新登录可继续填写；离开未保存页面时提示用户处理修改。
- 提交时统一校验全部必填项、附件、真实性确认及企业重复情况，并定位具体错误。
- 联系邮箱与登录邮箱分别保存，前者用于业务联系，后者用于身份验证和密码找回；本期不提供自助修改登录邮箱。
- 文件类型和大小在服务端再次校验，上传成功的文件才能用于提交；替换和删除文件不得破坏历史申请的附件。

### 4.3 提交与审批

| 编号   | 功能       | 业务规则                                                                             |
| ------ | ---------- | ------------------------------------------------------------------------------------ |
| ADM-01 | 正式提交   | 草稿或已驳回状态可提交；创建不可变申请快照和递增版本号，状态转为待审核               |
| ADM-02 | 待审核列表 | 默认按提交时间从早到晚排序；支持企业名称或信用代码搜索，以及品类、提交时间筛选和分页 |
| ADM-03 | 审核详情   | 展示本次快照、附件、介绍人姓名、提交时间及历次审批意见                               |
| ADM-04 | 审批通过   | 二次确认后通过；意见选填，同时生成正式供应商编号和档案                               |
| ADM-05 | 驳回申请   | 必须填写非空原因，原因上限 2,000 个字符；状态转为已驳回                              |
| ADM-06 | 修改重提   | 从最新申请初始化可编辑资料；重新提交形成新版本，旧版本和意见保持不变                 |
| ADM-07 | 审批历史   | 按提交版本展示提交时间、审核人、审核时间、结果、意见及当时资料                       |
| ADM-08 | 处理冲突   | 多人处理同一申请时，仅首次有效审批成功；其余操作提示状态已变化并刷新                 |

### 4.4 正式供应商档案

- 仅审批通过的企业出现在正式供应商名录中。
- 档案展示唯一供应商编号、企业信息、供应品类、联系人、资质、介绍人姓名、准入时间及审批历史。
- 供应商编号由系统生成且不可手动修改；建议格式为 `SUP` 加固定长度递增序号，允许不连续。
- 名录支持企业名称或信用代码搜索，以及供应品类、准入时间筛选和分页；介绍人姓名作为展示字段，本期不做人员归属统计。
- 供应商只能查看自己的正式档案，不能访问内部供应商名录。
- 已准入资料保持只读，本期不提供导入、批量导出或删除档案。

### 4.5 通知与历史追溯

| 事件               | 接收对象       | 必需内容                         |
| ------------------ | -------------- | -------------------------------- |
| 首次提交或重新提交 | 有效采购管理员 | 企业名称、提交时间、申请详情入口 |
| 审批通过           | 供应商主账号   | 审批结果、准入时间、档案入口     |
| 审批驳回           | 供应商主账号   | 审批结果、驳回原因、修改入口     |

介绍人不接收通知。站内通知必须可在收件箱查看已读和未读状态；通知详情入口仍执行实时权限校验。通知失败不能回滚已经完成的提交或审批，系统应记录发送失败并提供可追踪、可重试的处理方式。

关键操作记录至少覆盖账号与企业绑定、正式提交、审批、角色授予与移除，保存操作人、时间、对象和结果。提交、审批及档案记录不允许普通用户修改或删除；日志不记录密码、验证凭证等敏感信息。

## 5. 关键数据与一致性规则

| 数据对象     | 核心内容                                         | 关系与约束                                         |
| ------------ | ------------------------------------------------ | -------------------------------------------------- |
| 用户账号     | 邮箱、认证状态、账号状态                         | 复用系统身份能力；供应商与内部用户身份隔离         |
| 供应商企业   | 信用代码、当前状态、主账号、供应商编号、准入时间 | 信用代码唯一；主账号绑定一家企业；编号仅准入后生成 |
| 申请草稿     | 企业资料、联系人、供应品类、介绍人姓名           | 可编辑内容与正式提交快照分开保存                   |
| 准入申请版本 | 企业关联、版本号、提交资料及附件快照、提交时间   | 同一企业版本号唯一，提交后不可修改                 |
| 资质附件     | 材料类型、文件标识、企业及版本归属               | 历史引用的文件不得随草稿修改而删除                 |
| 审批记录     | 申请版本、审核人、结果、原因、审核时间           | 每个提交版本最多一个有效终审结果                   |
| 供应品类     | 名称、启停状态                                   | 历史引用保留，管理操作受权限控制                   |
| 通知与审计   | 接收对象、事件、发送状态及操作记录               | 复用系统能力，业务事件可追溯                       |

### 5.1 企业唯一性

统一社会信用代码在写入前规范化，使用数据库唯一约束防止并发重复；企业名称仅用于辅助提示。登记企业主体后，本期不支持自助修改信用代码，录入错误需联系管理员人工核实，不能通过修改代码切换到另一企业。

发现已有企业时，应提示“该企业已登记，请联系管理员核实”，不披露主账号、邮箱或联系方式。不能凭企业名称、信用代码或介绍人姓名自动取得已有企业的控制权，也不能自动合并企业。

### 5.2 提交与审批一致性

- 企业在任一时刻最多有一个待审核申请版本。
- 重复点击、网络重试及并发请求不产生多份申请或多次有效审批。
- 审批必须绑定具体提交版本，不能审批草稿或已经处理的版本。
- 审批通过、写入审批记录、生成编号和更新企业状态必须在同一事务中完成。
- 驳回结果、审批意见及状态同步保存，不能出现缺少意见的驳回记录。
- 档案以获批版本为依据；后续草稿或其他数据变化不能改写已批准的资料。

| 使用者     | 页面                           | 主要内容                                       |
| ---------- | ------------------------------ | ---------------------------------------------- |
| 未登录用户 | 注册、邮箱验证、登录、找回密码 | 自主注册，选填介绍人，验证账号                 |
| 供应商     | 入驻首页                       | 当前状态、下一步操作、最近审批意见             |
| 供应商     | 企业资料填写                   | 分组资料、附件、草稿保存和提交                 |
| 供应商     | 申请详情及历史                 | 各版本资料、审批结果、驳回原因                 |
| 供应商     | 我的供应商档案                 | 已准入后的只读档案                             |
| 采购管理员 | 准入申请列表                   | 待审核和已处理申请、搜索、筛选和分页           |
| 采购管理员 | 申请审核详情                   | 当前提交快照、附件、历史和审批操作             |
| 采购管理员 | 供应商名录与档案               | 已准入供应商查询和详情                         |
| 已登录用户 | 收件箱                         | 本人通知及业务详情入口                         |
| 授权管理员 | 用户、角色与权限               | 明确的用户授权、移除授权及有效权限查看         |
| 授权管理员 | 供应品类管理                   | 品类新增、更名和停用                           |
| 授权管理员 | 准入流程管理                   | 固定流程定义、标准状态图、受支持参数和执行历史 |

流程管理用于查看和管理实际使用的准入流程，不提供通用流程设计器。审批历史和流程执行历史分别满足业务追溯与运行诊断需求；配置只暴露系统实际支持且有授权控制的参数。

页面需覆盖首次使用、空列表、加载、请求失败、权限不足、附件失败及状态冲突等情形。所有用户可见文案提供中英文翻译，默认显示语言遵循应用设置。

## 7. 开发实施计划

下列任务按依赖顺序交付，每阶段均包含对应的数据、接口、页面、权限及验证工作，不以仅完成页面作为完成标准。

| 阶段           | 任务                                                   | 交付与验收门槛                                             |
| -------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| M1：身份与权限 | 供应商身份、邮箱验证、登录与找回、内部用户及角色管理   | 自主注册不能取得内部权限；不同身份进入对应功能；授权可管理 |
| M2：资料与草稿 | 企业主账号绑定、介绍人记录、品类管理、附件、草稿、查重 | 可保存并恢复资料；介绍人可留空；企业和附件按归属隔离       |
| M3：申请与审核 | 提交快照、状态机、待审列表、通过、驳回、重提及并发控制 | 首次通过和驳回重提两条业务路径完整可用                     |
| M4：档案与运营 | 正式编号、档案与名录、收件箱、审计、流程管理及失败重试 | 获批档案一致，相关人员收到提醒，历史和失败可追踪           |
| M5：交付验证   | 端到端联调、权限测试、数据库验证、部署配置检查         | 全部核心验收场景通过，邮件与文件存储在目标环境可用         |

### 7.1 开发约束

- 在应用内实现供应商业务，复用现有认证、权限、文件、通知与流程管理能力，开发前读取对应的项目本地 Skill。
- 数据表变更使用迁移，历史迁移不可覆盖；申请资料、快照和审批事务由服务端负责。
- 所有业务接口具备身份验证、操作授权、记录范围校验、输入校验及 API 文档声明。
- 表单及写操作使用应用现有提交保护机制，并对数据库唯一性和审批状态实施并发保护。
- 供应商能力通过受控注册结果和企业归属授予；内部角色通过用户管理明确分配，不能给全部登录用户授予业务管理员权限。
- 实现时同时交付实际使用能力的管理页面，包括用户与权限、品类及准入流程定义和执行历史。

### 7.2 上线依赖

- 配置对外可达的应用入口及邮件验证、密码找回回调地址。
- 配置邮件发送服务，验证注册和密码找回真实送达。
- 配置受权限保护的文件存储，验证部署后的上传、预览与下载。
- 初始化供应品类，明确首批采购管理员及系统管理员，并通过管理页面分配角色。
- 明确重复企业、主体信息填错、账号丢失等人工核实场景的实际联系渠道。
- 对数据库和附件建立可恢复的备份方案。

## 8. 验收场景

| 编号  | 场景                               | 预期结果                                                     |
| ----- | ---------------------------------- | ------------------------------------------------------------ |
| AC-01 | 不填写介绍人注册                   | 邮箱验证后可登录，不影响申请和审批                           |
| AC-02 | 填写介绍人注册                     | 姓名带入草稿、提交快照和获批档案；不产生账号关联、授权或通知 |
| AC-03 | 重复邮箱或失效验证凭证             | 不产生重复有效账号，验证失败有明确反馈                       |
| AC-04 | 保存不完整草稿后重新登录           | 已保存资料恢复，未提交资料不出现在采购审批队列               |
| AC-05 | 缺少必填资料或营业执照提交         | 提交被阻止，定位缺失项，不生成待审核版本                     |
| AC-06 | 上传超限或非允许格式文件           | 服务端拒绝；上传失败的文件不能用于提交                       |
| AC-07 | 完整资料首次提交并通过             | 生成版本和审批记录，产生唯一编号及只读档案，进入正式名录     |
| AC-08 | 驳回时不填写原因                   | 操作失败，申请仍待审核                                       |
| AC-09 | 驳回后修改介绍人和资料并重提       | 生成新版本；采购端只见正式提交版本；旧资料和意见仍可查看     |
| AC-10 | 待审核或已准入时尝试修改资料       | 页面不可编辑，直接接口调用同样被拒绝                         |
| AC-11 | 另一账号登记相同信用代码           | 不创建重复企业，不泄露已有账号信息，不允许自动认领           |
| AC-12 | 重复提交或多管理员并发审核         | 只产生一个待审核版本及一个有效审批结果，其余请求得到明确反馈 |
| AC-13 | 供应商访问其他企业或附件           | 页面和直接接口均拒绝，不能通过文件地址绕过                   |
| AC-14 | 普通供应商或未获审批权限的用户审批 | 操作被拒绝，不产生审批记录或状态变化                         |
| AC-15 | 移除采购管理员角色后再次操作       | 权限及时生效，原用户不能继续审核                             |
| AC-16 | 通知服务失败                       | 业务结果仍正确保存；失败有记录且可重试，不重复审批或建档     |
| AC-17 | 审批事务中途失败                   | 不留下半成品编号、审批记录或准入状态；恢复后可安全重试       |
| AC-18 | 旧申请附件被新草稿替换             | 旧版本仍可查看和下载其原始附件                               |
| AC-19 | 查看页面、管理入口和流程记录       | 中英文文案完整；功能与权限一致；固定准入流程及历史可查       |
| AC-20 | 使用密码找回和退出                 | 重置凭证一次有效且过期后不可用，退出后受保护接口拒绝旧会话   |

## 9. 完成定义

供应商能够自主注册并选填介绍人，填写资料后提交申请；采购管理员能够通过或说明原因后驳回；供应商能够修改并重新提交；审批通过后形成唯一正式档案。整个过程具备有效的数据隔离、提交版本、审批历史和结果提醒，且不存在业务员引入或邀请流程的交付依赖。

交付验证应覆盖受影响页面、接口、数据库迁移与权限行为，并完成自主注册通过、驳回重提、并发处理及越权访问的端到端验证。文档描述的是开发需求与验收目标，不代表对应功能已经实现。
